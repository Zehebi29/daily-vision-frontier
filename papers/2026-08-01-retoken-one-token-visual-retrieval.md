# 🎯 给视觉模型配一个「检索专家」——用一个小 token 在图片堆/长视频里精准「找重点」

> **Paper**: ReToken: One Token to Improve Vision-Language Models for Visual Retrieval
> **arXiv**: `2607.28627`
> **Published**: 2026-07-30 | **Authors**: Yao Xiao, Reuben Tan, Zhen Zhu, Yuqun Wu, Jianfeng Gao, Derek Hoiem（UIUC & Microsoft Research & Google DeepMind）
> **Links**: [arXiv](https://arxiv.org/abs/2607.28627) | [PDF](https://arxiv.org/pdf/2607.28627)

---

## 📝 一句话总结

**这篇论文相当于给 AI 配了一位受过专业训练的「图书检索专家」——你提问时，专家不再把整座图书馆的书都翻一遍，而是用鼻子闻一闻每本书的「实际内容」，直接把最相关的几本叼到你面前；而这位专家，只是一只经过特训的「嗅探犬」——也就是一个可学习的小 token。**

更具体地说：视觉大模型（VLM）在处理「一堆图片」或「一小时视频」时，往往只有一两张图、一两秒是关键（就像草垛里的一根针）。旧方法靠模型的「注意力分数」找重点，但注意力在视觉模型里是个不靠谱的信号（长视频上找对率只有 5.1%，跟瞎猜差不多）。这篇论文发现：Transformer 里常被忽视的 **Value（值）向量** 比 **Key（键）向量** 携带强得多的检索信号，于是训练了 **一个可学习的 token（ReToken）**，让它学会用 Value 空间给每一帧打分、挑出最相关的少数几帧。效果：图像任务最多提升 13.4 分，而且**只用图片训练过**的 ReToken，零样本迁移到「一小时长视频」问答还能涨 8 分。

## 🧐 这论文在干什么？（用大白话）

### 这解决的是什么问题？

> 🏛️ **设想一下：你走进一座藏书一百万册的图书馆，对管理员说：「帮我找一本讲『奶牛』的书。」**
>
> 管理员有两种做法：
> 1. 把一百万册书全搬到你面前让你自己翻——你翻到天黑也翻不完；
> 2. 先快速定位，只把最相关的两三本拿给你。

现在的视觉大模型（VLM，比如 Qwen3VL、InternVL）基本用的是做法 1：把所有图片、所有视频帧都变成「视觉 token」一次性塞进模型，让模型自己找答案。图片少的时候没问题，但一出现两种情况就崩了：

- **干扰项太多**：你给它 50 张照片，问「有奶牛的那张图里有没有卡车？」——只有一张图相关，另外 49 张全是「干扰项」（distractors）。模型被淹没，准确率直线下降。
- **输入太长**：一小时的视频按 0.5 帧/秒采样有 1800 帧，每帧 196 个 token，总共约 35 万个 token——GPU 内存根本放不下，直接报 OOM（内存溢出）。

所以，处理长视觉输入，本质上就是一个 **检索问题（retrieval）**：先选出少数「相关」的帧/图片，再从里面找答案。这就是论文说的「在一堆草垛里找一根针」——他们用的基准数据集就叫 **Visual Haystacks（视觉草垛）**。

### 以前的方法为什么不行？

> 过去人们怎么找书呢？两条路，各有各的问题：

**路线一：外挂一个「找图系统」（如 CLIP、SigLIP2）**
先让一个独立的图片-文字匹配模型选出相关图片，再喂给 VLM 回答。

> 就像图书馆门口雇了一个「前台」先帮你筛一遍书。问题：前台和读者是两个人，前台筛的书读者不一定满意（检索器和 VLM 是两套系统，信息有损耗），而且每张图都要被重新编码一遍，又慢又费显存。

**路线二：用模型自己的「注意力分数」当检索信号（如 ReKV）**
大语言模型（LLM）处理超长文本时，注意力分数能指出「哪些词最重要」，于是有人照搬到视觉上：看问题 token 对每一帧的注意力有多高，分数高的就是相关帧。

> 就像让图书管理员只靠「书名」判断哪本书有用。书名常常骗人——《牛与经济学》可能根本不是在讲牛。论文用数据证明了这一点：在长视频问答 QAEgo4D 上，注意力检索的找对率平均只有 **5.1%**——20 次里找对 1 次，基本等于瞎蒙。

**为什么注意力在视觉上这么不靠谱？** 论文给了两个原因：

1. **注意力天生不是干检索的**：它是训练来「预测下一个词」的，从来没学过「挑重点」；
2. **训练数据里没有「干扰项」**：视觉模型的训练数据（比如「看图说话」）里，几乎所有图片都和问题相关，模型从来没有遇到过「要在一堆无关图里挑一张」的情况，自然学不会挑。

## 💡 核心思想（第一性原理）

### 核心洞察

论文做了一个非常关键的诊断实验：**检索时别用 Key，用 Value。**

先科普 Transformer 注意力层里每个 token 的三个向量：

- **Query（查询）**：我「想要找什么」
- **Key（键）**：我「是什么」——相当于每本书书脊上的标签
- **Value（值）**：我「实际的内容」——相当于书里的正文

经典的注意力公式（Query 和 Key 做内积）决定「谁注意到谁」，但真正被传播到下一层的，是 **Value**。论文发现：**在 Value 空间做检索，比在 Key 空间准得多**——在「两图挑一」的受控实验里，把检索分数从「问题均值 × 平均 Key」换成「问题均值 × 平均 Value」，找对率从 65.7% 涨到 78.0%（Qwen3VL，InternVL3.5 上从 78.8% 涨到 83.8%）。

用大白话说：**书名（Key）只是用来路由的标签，正文（Value）才是真正的内容。想找「讲奶牛的书」，闻一闻书里的内容，比看一百遍书名有用。**

### 方法拆解

#### 第一步：训练一只「嗅探犬」——ReToken 本身

ReToken 就是一个**可学习的向量**（一个 token，维度与模型隐藏层相同），训练时拼在问题文字的末尾，跟着问题一起送进模型。模型读完问题后，这个 token 在最后一层输出一个「总结向量」——相当于专家听完你的请求后，脑子里形成了一个「我要找的东西长什么样」的模板。

- **训练方式**：给模型看多图问答数据（MIRAGE 数据集），每张图标注「相关/不相关」。把每一帧的平均 Value 向量和 ReToken 的输出向量算**余弦相似度**（两个向量方向越像，分数越高），然后用**类别平衡的二元交叉熵损失**训练——让相关帧分数高、不相关帧分数低。（简单说：正样本和负样本分开平均，防止「49 张无关图」把「1 张相关图」的梯度淹没。）
- **关键点**：**模型本体（VLM）完全冻结不动**，只训练这 1 个 token + 1 个投影矩阵。全部新增参数就这么多，所以训练极快——单张 H100，约 4 小时，3 个 epoch。
- **类比**：你不是重新培训整个图书馆的员工，只是特训**一只嗅探犬**——狗狗学会「闻内容」（Value），其他一切照旧。

#### 第二步：推理时「先找书，再读书」（两遍推理）

提问时分成两个阶段：

**第一遍（检索 pass）**：把问题和 ReToken 拼在一起过一遍模型，在最后一层给每一帧打分，选出分数最高的 K 帧（比如 K=16）。

> 类比：嗅探犬先跑一趟书架，用鼻子扫过所有书的内容，叼回最相关的 K 本书。

**第二遍（回答 pass）**：只把这 K 帧的缓存喂给模型，正常生成答案。

> 类比：读者只读专家叼回来的几本书，轻松回答。

**视频场景还有一个妙招：一次编码，多次提问。** 视频先被逐段编码进一个持久的 KV 缓存（相当于图书馆的书架提前摆好、编好索引），之后不管问多少个问题，都直接在这个缓存上「检索 → 回答」，不需要重新看视频。问的问题越多，省得越多。

#### 第三步：长视频的特殊处理（粗筛 → 精排）

长视频帧数太多，早期层的注意力预算放不下全部缓存。ReToken 采用「粗筛」策略：每一层先用 Value 相似度筛出 Top-256 帧，只让 ReToken 在这 256 帧上做注意力；最后一层再精排，选出最终要用的 K 帧。

> 类比：嗅探犬先快速跑过大半个图书馆，把范围缩小到 256 本书，再仔细闻一遍，最后确定最相关的几本。

### 🎭 贯穿全文的类比

> **整个方法就像给一座巨大的图书馆配了一位训练有素的「检索专家」（一只嗅探犬）：**
>
> - **图书馆的藏书** = 输入的所有图片/视频帧（编码后存进 KV 缓存的视觉特征）
> - **读者的问题** = 提问文字（query）
> - **老办法（注意力检索）** = 只认书名的实习生，书名常常骗人，找对率 5%
> - **Value 空间** = 书里的实际正文（Key 只是书脊上的标签）
> - **ReToken（一个 token）** = 特训过的嗅探犬，学会用「内容」而不是「标签」找书
> - **Top-K 帧** = 狗狗叼回来的几本书，读者只读这几本
> - **两遍推理** = 专家先跑去找书，读者再坐下来读书
> - **一次编码、多次提问** = 书架只整理一次，所有读者都能用

## 🔬 实验怎么说？

### 关键结果（用白话）

| 他们想验证什么？ | 怎么验证的？ | 结果怎么样？ |
|----------------|------------|------------|
| 干扰项越多，ReToken 的帮助是不是越大？ | 在 Visual Haystacks 基准上，从 2 张图一路加到 100 张图（始终只有 1 张相关），看准确率 | 干扰越多提升越大：2 张图时 +3.9 分，10 张图 +11.5 分，50 张图 **+13.4 分**（58.6% → 72.0%），100 张图 +12.0 分。原来 50 张图时每 100 题错 41 题，现在只错 28 题 |
| ReToken 比「注意力检索」准多少？ | C=50 时只检索 1 张图（K=1），比找对率（recall） | ReToken 找对率 64.7%，注意力检索（ReKV）只有 **1.8%**——注意力基本找不到那张对的图，ReToken 能找到近 2/3。两者都不是上限，Oracle（直接告诉它正确答案在哪）是 80.7% |
| 只训图片，能不能迁移到视频？（零样本） | 只用图片数据训练过的 ReToken，直接测长视频问答 | 能！LVBench（平均 68 分钟/个视频）+8.0 分（40.6% → 48.6%），Video-MME +2.0 分，QAEgo4D 在 K=1 时 +6.8 分。就像用中文材料训练出的检索专家，直接去英文图书馆干活，居然挺好使 |
| 速度/显存代价大吗？ | 单张 H100 上测「每个问题」的耗时 | 视频编码一次约 14.7 秒（可当预处理，所有问题共享），检索阶段只额外增加约 0.4 秒/问题；训练也只要约 4 小时。小团队也能复现 |

### 消融实验说明了什么？

1. **Value vs Key**：把 ReToken 的检索分数从「平均 Value」换成「平均 Key」，找对率从 64.7% 掉到 59.4%。→ 说明「闻内容」确实比「看标签」有用，直接验证了核心洞察。
2. **微调前几层**：把模型前 1–3 层也放开训练，图像任务还能再涨（准确率 75.0%），但视频任务反而变差（58.0% vs 冻结时的 60.0%）。→ 在图片上微调模型会造成「领域偏移」，换到视频反而水土不服；冻结 VLM、只训 token 反而更稳、更好迁移。
3. **两遍推理的必要性**：如果只跑一遍（每一层各自检索、直接回答），准确率从 72.0% 掉到 50.4%。→ 因为 ReToken 只在最后一层被训练过检索信号，必须「最后一层选帧，广播给所有层」。
4. **什么题最受益**：LVBench 按题型拆开看，帮助最大的是「关键信息检索」（+15.4）和「实体识别」（+10.5）——证据集中、能指名道姓的问题；**「总结概括」反而掉 5.2 分**——总结需要看全部内容，集中检索的假设在这里不成立。

## ⚠️ 哪里还不够好？

1. **两遍推理的开销**：每次提问都要跑两遍前向，检索 pass 多花约 0.4 秒/问题，显存也略多占一点。
   > 就像找书要先让专家跑一趟书架再回来读——对急性子的读者来说，多等了几秒。
2. **「单帧打分」的局限**：每帧是独立打分的（取该帧所有 token 的平均 Value），如果关键证据只占画面里几个 token，会被平均稀释掉；跨帧组合才出现的信息（「我进门之前发生了什么」）也抓不住——ReToken 只会定位「事件本身」，不理解时间先后。
   > 就像只看一张张孤立的照片，看不出相册的叙事顺序。
3. **总结类任务反而更差**：证据分散在整个视频时，均匀采样（每段都看一点）反而比集中检索好。ReToken 的「集中」假设在「概括全片」上失灵。
   > 就像问「这本书整体讲了什么」时，最好的办法是通读，而不是只精读三页。
4. **训练数据只有图片**：没有用过视频数据，视频上的表现属于「意外之喜」，时序结构并没有被真正学到（作者自己承认，加入视频数据训练应该会更好）。
5. **效果对训练充分性敏感**：InternVL3.5 在 100 张图时提升只有 +4.4 分，作者归因于训练预算不足（只训了 1 个 epoch，因为 InternVL 每张图的 token 更多、更贵）。
   > 就像狗狗训练时间不够，鼻子还没那么灵。

## 🔗 跟其他工作的关系

```
[CLIP (2021)] — 图片-文字对齐的「外部检索器」：先挑图，再重新编码喂给模型
  └── [SigLIP2 (2025)] — 更强的对齐，但仍是两套系统：检索器和 VLM 分离
       └── 问题：外部检索有信息损耗、还得重新编码一遍，又慢又费

[InfLLM (2024)] — NLP 里用 query-key 注意力分数选相关 KV 块
  └── [ReKV (2025)] — 把注意力检索搬到视觉域
       └── 问题：VLM 的注意力信号不可靠（长视频找对率仅 5.1%）
            └── [ReToken (2026，这篇)] — 诊断出 Value 空间信号更强，
                用 1 个可学习 token 显式训练「检索专家」，
                冻结 VLM、只训 token + 投影矩阵，还能零样本迁移到视频

[BLIP-2 Q-Former (2023)] — 用 32~64 个可学习 query token 压缩视觉特征
  └── [ReToken] — 只需要 1 个 token，定位从「压缩」变成「检索」，
      还带显式的检索损失监督
```

## 🌍 如果这个能实际用上…

1. **长视频问答助手**：对一小时的监控录像、会议录像提问——「穿红衣服的人几点进的门？」「PPT 第 30 分钟讲了什么？」——AI 不再需要把整段视频重新看一遍，直接在缓存上检索 + 回答。
2. **给图片/视频 RAG 装「视觉检索器」**：现在的检索增强生成（RAG）主要面向文本；ReToken 提供了一种把图片和视频也变成「可检索数据库」的轻量方案——多个问题共享一次编码，问得越多越划算。
3. **移动端/边缘设备的多图理解**：训练只要单张 H100、新增参数只有 1 个 token，小团队甚至个人开发者也能给开源 VLM 加装「找重点」的能力。
   > 这就像给每一座图书馆（大模型）配一只不占地方、训练便宜、却极其高效的嗅探犬（一个小 token）——它不需要重新装修图书馆，就能让找书快十倍。
